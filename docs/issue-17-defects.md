## D01 · `pow(10, α)` 在 10^−324 及更小处符号反转

**分类**：bug

**复现**
```js
MetaNum.pow(10, -324).lt(1)          // 期望 true，实际 false
MetaNum.pow(10, -324).toString()     // 实际 "E324"（正指数）
MetaNum.pow(10, -324).mul("1e324")   // 实际 E648（≈10^648），期望 ≈1
```

**证据**（脚本 D01 段）

| 输入 | array | toString | format | 判定 |
|---|---|---|---|---|
| `pow(10,-320)` | `[[320.000004834948,1]]` | `9.99989E-321` | `1.000E-320` | 正常 |
| `pow(10,-323)` | `[[323.0051853474518,1]]` | `9.88131E-324` | `1.012E-323` | 正常 |
| `pow(10,-324)` | `[[324,1]]` | `E324` | `1.000E324` | **符号翻转** |
| `pow(10,-325)` | `[[325,1]]` | `E325` | `1.000E325` | **符号翻转** |

**根因假设**：`10^−324` 已低于 IEEE-754 次正规数下限（≈5e−324）。该库对负指数用 `[幂, 1]` 形式表示时，在越过 double 下限后
未保留负号（或先经 `Math.pow` 溢出为 `±Infinity`/`0` 再被错误规范化）。

**期望**：`pow(10, α)` 对任意有限 α 都应满足 `pow(10,α) < 1 ⟺ α < 0`；`pow(10,-324)` 应为 `10^-324`（可接受次正规精度损失）。

**验收标准**
- [ ] `pow(10,-324).lt(1) === true`，`pow(10,-325).lt(1) === true`，`pow(10,-350).lt(1) === true`
- [ ] `pow(10,-324).mul("1e324").eq(1)`（在容差内，`eq_tolerance` 视精度）
- [ ] `pow(10,α)` 在 α ∈ {−308 … −400} 上单调：α 越小值越小
- [ ] `pow(10,-320..-323)` 保持现有正确行为不回归

**影响**：游戏《失控 AI 增量》只处理大数（≥1），**基本不受影响**；属库的数值健全性问题。

## D02 · `toBeaf()` 值 > MSI 时丢失底数

**分类**：bug

**复现**
```js
MetaNum.BEAF(10, 15).toBeaf()  // "{1000000000000000}"  正确
MetaNum.BEAF(10, 16).toBeaf()  // "{16}"                错误
MetaNum.BEAF(10, 100).toBeaf() // "{100}"               错误
```

**证据**（脚本 D02 段）

| 输入 | array | toString | toBeaf |
|---|---|---|---|
| `BEAF(10,15)` | `[[1000000000000000]]` | `1000000000000000` | `{1000000000000000}` |
| `BEAF(10,16)` | `[[16,1]]` | `E16` | `{16}` |
| `BEAF(10,100)` | `[[100,1]]` | `E100` | `{100}` |

**根因假设**：`toBeaf()` 对「`[e,1]` 形式（10^e）」只取了指数 `e`，未还原为 2 项 BEAF `{10, e}`
（也未按科学记数还原 base）。即对 > MSI 的值走了分支但拼装错误。

**期望**：`a^b` 的 `toBeaf()` 应能表达该值：至少 `{10,16}`（2 项 BEAF），或科学记数形式；不得退化为 `{16}`。

**验收标准**
- [ ] `BEAF(10,16).toBeaf()` 不返回 `{16}`
- [ ] `MetaNum(BEAF(10,16).toBeaf()).eq(BEAF(10,16))`（**往返一致**）
- [ ] `fromBeaf('{10,16}').toBeaf()` 往返一致
- [ ] `BEAF(10,15)`（< MSI）行为不回归

**影响**：影响任何把 metanum 值导出为 BEAF 文本的功能；游戏目前不依赖 BEAF 显示，但属公开 API 缺陷。

## D03 · `toBeaf()` 3+ 项 LAN 输出内部数组 dump

**分类**：bug（与 D02 同属 `toBeaf` 分派问题）

**复现**
```js
MetaNum.BEAF(10, 2, 1, 1, 2).toBeaf()
// 实际 "{ [10], [9, 1, 8], [8, 2, 8], …, [8, 9, 9] }"（内部 array dump）
MetaNum.BEAF(4, 5, 6, 7, 8, 9).toBeaf()
// 实际同样是内部 array dump
```

**证据**：见脚本 D03 段（输出以 `{[10], …}` 形式出现，即 array 元素被逐行 `JSON` 化）。

**根因假设**：`toBeaf()` 对 3+ 项的「序数运算」结果没有可读的 BEAF 表示分支，直接回退到打印 `array`。

**期望**：要么给出可读的 BEAF 文本（如 `{10,2,1,1,2}`），要么明确抛「不可表示」错误——**不应输出内部结构**。

**验收标准**
- [ ] `toBeaf()` 输出中不得出现 `[` `]` 之类内部 array 字面量
- [ ] 对可表示者往返一致：`fromBeaf(x.toBeaf()).eq(x)`
- [ ] 对不可表示者有明确行为（抛错或降级为科学记数），且文档写明

**依赖**：可表示范围需在 `notation-semantics.md` §BEAF 中定义。

## D04 · `format()` 重复单字母折叠错误

**分类**：bug（`format-metanum.js`）

**复现**
```js
format(MetaNum("Z152416"))    // "1.000Z152,416"   正确
format(MetaNum("ZZ152416"))   // "1.000Z3"         错误
format(MetaNum("ZZZ152416"))  // "1.000Z4"         错误
format(MetaNum("ZZZZ152416")) // "1.000Z5"         错误
```

**证据**（脚本 D04 段）：`ZZ152416` 的 array 为
`[[…],[8,20],[152414,21],[1,22]]`，`toString` 给出 `1Aa22 152414Aa21 …`（信息完整），
但 `format` 折叠成 `1.000Z3` —— **尾部的 `[1,22]` 被错误地当成"再一个 Z"计数**。

**根因假设**：`format-metanum.js` 的字母链/多字母折叠对「单字母重复 + 后续高阶行」的组合计算错误，
把行 `[k,22]`（ω 指数层）误读为单字母计数器。

**期望**：`format(ZZ152416)` 应保持与 array/`toString` 一致的数值；不得因多一个 `Z` 只把数字 +1。

**验收标准**
- [ ] `format(MetaNum(s))` 与 `format` 的**往返一致**：解析 format 输出应回到原值（若有 parser）
- [ ] `format(ZZ152416) ≠ "1.000Z3"`，且 `Z`/`ZZ`/`ZZZ` 三者的 format **单调递增**
- [ ] `format(Z152416)` 现有正确输出不回归

**影响**：所有依赖 `format()` 的展示层（含游戏内若未来接入 letter notation）。

## D05 · `!Aa`（非整数 α）解析为 0

**分类**：bug

**复现**
```js
MetaNum("!Aa0.5")  // array [[0]]，toString "0"
MetaNum("!Aa1.5")  // array [[0]]
MetaNum("!Aa2.5")  // array [[0]]
```

**证据**（脚本 D05 段）。对照：整数 α 正常——`!Aa1 → Aa1`、`!Aa2 → Aaa2`、`!Aa10 → Aaaaaaaaaaa10`。

**语义依据**（[`notation-semantics.md`](notation-semantics.md) §1，决策 1B）：
> `!Aaα ≡ A(a×⌊α⌋)(α)`（α ≥ 1）

因此 `!Aa1.5 = Aa1.5`、`!Aa2.5 = Aaa2.5`，**不是 0**。README 的 `10{ω^int(α)·frac(α)}10` 在整数处自相矛盾，已按决策 1B 重新定义（见规范 §6）。

**根因**：符号记法的解析只处理整数 α，小部分落到默认分支返回 0。

**验收标准**（已过）
- [x] `MetaNum("!Aa1.5").neq(0)`，且 `= Aa1.5`
- [x] `!Aa0.5/1.5/2.5/3.5` 非零且严格单调
- [x] 整数 α 路径不回归（`!Aa1=Aa1`、`!Aa2=Aaa2`、`!Aa5=Aaaaaa5`）

**已修复**（`fromString` 新增 `!Aa<real>` 分支）。

## D06 · `!αAaβ`（非整数 α）解析为 0 / 畸形

**分类**：bug

**复现**
```js
MetaNum("!1.5Aa4")  // array [[0]]，toString "0"
MetaNum("!1Aa1.5")  // array [[0]]
MetaNum("!2.5Aa4")  // toString "! [1] [2.5,4]"，layer 1（畸形）
```

**语义依据**（README）：
> `!αAaβ = !Aa(β + log α)`，`!2.0000Aa4 = 10{ω^4}10`。

对照 `!2.0000Aa4` 可解析（`Aaaaa4`）。

**状态**：✅ **已修复（A1，Phase 2）**。`!αAaβ` 现按 `!Aa(β+log₅(α/2))` 映射到真实值；formatter 新增去层形状分支，输出可往返的 `!α Aa β`。

**验收标准**（已过）
- [x] `!αAaβ`（α 为一般实数）不再返回 0 / 畸形
- [x] 与 `!Aa(β+log₅(α/2))` 的换算一致（见规范 §2）
- [x] `format(!2.5Aa4) == "!2.500Aa4"` 且往返；`!2.376Aa999` 往返；`!2.0000Aa4` 不回归

**残余**：`@`/`#` 等高符号层与 x<2 的 mantissa 精度往返（见规范 §2「已知残余」），单独跟踪。

**依赖**：同 D05，需 `notation-semantics.md`。

## D07 · `2{λ}2 ≠ 4`（λ ≥ ω^ω·2）

**分类**：**SPEC + bug**

**复现**
```js
new MetaNum(2).aperionate(2)   // 2{ω^2}2       → 4      ✓
new MetaNum(2).iter(2)         // 2{ω^ω}2       → 4      ✓
new MetaNum(2).cuboiter(2)     // 2{ω^ω·2}2     → !AaF10 ✗
new MetaNum(2).expoiter(2)     // 2{ω^(ω+1)}2   → !AaAa10 ✗
new MetaNum(2).trioterate(2)   // 2{ω^(ω·2)}2   → !Ac10  ✗
new MetaNum(2).trixxate(2)     // 2{ω^(ω^2)}2   → !Bk10  ✗
new MetaNum(2).aperixxate(2)   // 2{ω^(ω^ω)}2   → 2ε1    ✗
```

**证据**：脚本 D07 段。对照：`BEAF(2,2,1,1,2)`（= 2{ω^2}2）→ 4 ✓；且 `3{λ}1 = 3` 在同样层级 ✓。

**语义依据**（README rule 3）：
> `n{λ}b = n{λ[b]}n`

当 `b = 2` 时 `2{λ}2 = 2{λ[2]}2`，无论 λ 多高，最终都应坍缩到 `2{2}2 = 2² = 4`。
`b = 1` 时 `3{λ}1 = 3`（已通过）。故 `2{λ}2` 在**所有** λ 上都必须 = 4。

**根因假设**：`b = 2` 且 λ 进入 ω^ω·2 及以上的「对角化/极限」分支时，基数列 `λ[b]` 未正确下降，
导致直接把 λ 当作极限写下（`!AaF10` 等），而不是归约到下一层。

**期望**：`2{λ}2 = 4` 对所有序数 λ 成立；`2{λ}1 = 2`；`n{λ}1 = n`。

**验收标准**
- [x] `2{λ}2 = 4`（`iter/itermult/cuboiter/expoiter/trioterate/trixxate/aperixxate/epsilonate`，Phase 2 快速路径）
- [ ] `x.{各层}(2)` 对 x=3,4,5 分别 = x²  ← **已作废**：与 rule 3 矛盾（`3{ω}2=3{2}3=3↑↑3`）。正确判定见规范 §3
- [x] `x.{各层}(1) = x`
- [x] 现有 `2{ω^2}2`、`2{ω^ω}2` 结果不回归
- [ ] 序数层单调：`x{λ}2` 对 λ 单调不降

**状态**：◑ **B2-a 已实现**（部分）。

**验收标准**
- [x] `2{λ}y = 4` 对 10 个无限层方法（`aperiote/aperionate/iter/itermult/cuboiter/expoiter/trioterate/trixxate/aperixxate/epsilonate`）与整数 `y≥2` 全部成立（规范 §3 / `d07-engine-design.md` §7）
- [x] 有限层不误伤：`2{1}3=8`、`2{2}3=16`
- [x] `x.{各层}(1) = x`
- [x] 现有 `2{ω^2}2`、`2{ω^ω}2` 结果不回归
- [ ] `x.{各层}(2)` 对 x=3,4,5 = x²  ← **已作废**：与 rule 3 矛盾（`3{ω}2=3{2}3=3↑↑3`）
- [ ] 序数层单调：`x{λ}2` 对 λ 单调不降

**B2-b..d（x≥3 精确化）不做**：`3{ω^ω·2}2` 的精确级联是天文数字，超出表示能力；marker 是合理的渐近近似。若未来需要，需先引入中间序数正规形与预算截断，建议单开 issue。

**依据**：`notation-semantics.md` §3（`λ[b]` 已形式化）；设计见 `d07-engine-design.md`。

## S01 · 规范缺失（spec gap）

README 描述的是**设计意图**，但对本次要修的边界缺少可执行定义：

1. 单字母记法 `E…Z` 的**规范形**与重复规则（D04）；
2. 符号记法 `!Aa`、`!αAaβ` 的 `int/frac` 拆分与换算（D05/D06）；
3. 基数列 `λ[b]`（rule 3）在极限序数处（D07）；
4. `toBeaf()` 的**可表示范围**与"不可表示"行为（D02/D03）；
5. `pow` 在小数量级（double 次正规以下）的语义（D01）。

→ 这些构成 [`notation-semantics.md`](notation-semantics.md) 的写作清单。

## F01 · 功能请求（非缺陷，暂缓）

Issue #17 末尾提议用分隔符（`|`、`!Ab`、`!Ac` …）表示 ω^ω+n、ω^ω·n 直到 ω^(ω^ω) 之间的值。
这是**新增记法**，不是修 bug。本次不纳入；待 D07 语义规范稳定后再单独评估（可开独立 issue）。
